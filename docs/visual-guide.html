三层结构

渲染层：panel/ 与 brain/ 只负责 UI；服务层：service/ 持有 CDP、窗口句柄、REST 写队列；知识层：Obsidian vault（D:\brain）与任务卡。

面板从不直接连 Obsidian，一切经过宿主代理 → guest service。

镜像原理

Obsidian 以 --remote-debugging-port 启动，服务用 CDP 截帧（JPEG），面板长轮询 surface-frame 渲染到 canvas，并把指针/滚轮/键盘/IME/粘贴转成 surface-input。

闭环

知识库项目 → 任务卡 → 派发 Agent → 会话归档回写任务卡 → 复制/导出。所有状态都落在 vault 的 Markdown frontmatter 里，可被 Dataview 查询。

多金库

一个 Obsidian 进程可开多个窗口，每个窗口一个 vault；服务按标题匹配 target，面板顶部标签切换，无需重启。

设计取舍

  • 不用 service.surface：宿主 dock 无法承载分栏，改为在 panel.entry 内自绘。
  • 不用网页版 Obsidian：必须真实本地窗口，才能复用插件与本地文件。
  • 不重排 D 盘编号：brain 是知识层，D 盘是资产层，用台账映射。
  • 写操作单队列 + 文档版本号（If-Match），412 自动重试。
已知限制：宿主 Electron 渲染器无 DevToolsActivePort，无法 CDP 挂 UI；验证依赖假宿主 harness 与人工 Ctrl+R。宿主不广播 settings 变更，新项目需刷新左栏。

归档流水线

1
读取会话

GET /api/session/{id}，判断 idle（time.updated ≤ time.idle）。

2
分页拉消息

limit=200&order=asc，之后只用 cursor.next（不能再带 order）。

3
渲染

按用户回合分组；助手正文保留，工具调用折叠进 <details>。

4
写文件

会话记录/<项目>/<标题>-<YYYY-MM-DD>.md，frontmatter 记 session_id。

5
回写任务卡

archive_path / archived_at / session_updated；同名会话按 session_id 去重。

自动归档规则

  • 每 60 秒检查一次已派发任务；仅当会话空闲且有新内容才写。
  • auto: true 跳过 busy / unchanged / empty；force: true 强制重写。
  • 任务卡 frontmatter 设 auto_archive: false 可关闭该任务。
  • 实测样本：2735 条消息 / 48 轮 / 461 KB。
